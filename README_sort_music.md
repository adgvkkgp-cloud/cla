# sort_music — раскладка песен по папкам радиостанций

Скрипт для музыкальных модов Hearts of Iron IV (и других игр Paradox с таким же
форматом): читает файлы станций и раскладывает `.ogg` по папкам — по одной папке
на станцию.

**Песни копируются, а не перемещаются.** Оригиналы остаются лежать в папке `music`,
игра/мод продолжает работать как раньше.

## Как пользоваться

1. Положить `sort_music.ps1` и `sort_music.bat` в ту самую папку `music`
   (рядом с `0_radio_*.txt` и `.ogg`).
2. Двойной клик по `sort_music.bat`.
3. В папке появятся `radio_bbc`, `radio_berlin`, `radio_madrid`, … с копиями песен.

Сначала можно посмотреть, что будет сделано, ничего не трогая — запустить из
PowerShell в этой папке:

```powershell
.\sort_music.ps1 -DryRun
```

## Как скрипт определяет файлы станций

Имя txt-файла не важно (`0_radio_madrid.txt`, `my_station.txt` — без разницы).
Скрипт берёт **все** `.txt` рядом с собой и оставляет те, внутри которых есть строка

```
music_station = "radio_madrid"
```

Имя папки берётся из этой строки. Песни — все записи вида

```
song = "a_las_barricadas"
```

внутри блоков `music = { ... }`, независимо от того, какие там `chance`/`modifier`
(проверено на `radio_madrid` — простые `factor = 1`, и на `radio_berlin` — с
`has_war`/`threat`/`has_government`) и записан ли блок в одну строку или в
несколько. Так что любой новый файл станции подхватится сам, ничего править не нужно.

Учтено:

- закомментированные (`#`) песни игнорируются;
- повторы внутри файла не дублируются;
- песня, которая есть в нескольких станциях, копируется в каждую папку;
- повторный запуск ничего не копирует заново (`-Force` — перезаписать);
- файлы станций в UTF-8 и в windows-1252 читаются одинаково.

## Как песня ищется среди файлов

Три захода, в этом порядке:

1. **По `.asset`-файлам мода.** В HOI4 связь «имя песни → файл» задаётся там:
   `music = { name = "ye_lai_xiang" file = "夜来香.ogg" volume = 0.65 }`.
   Если такие файлы лежат рядом, скрипт их читает и берёт имя файла оттуда.
2. **По точному имени файла**, регистр не важен.
3. **По «упрощённому» имени** — снимается диакритика, разделители приводятся к
   одному виду. Поэтому `song = "di_er_meng"` находит `Dì_èr_mèng.ogg`, а
   `"ai_ni_sanbai_liushi_nian"` — `Ài_nǐ_sānbǎi_liùshí_nian.ogg`. Именно из-за
   этого китайские и японские треки раньше не копировались.

Иероглифы и кириллица при упрощении не трогаются, так что разные имена не
слипаются в одно. Если два файла всё же дают одно упрощённое имя, оба
сопоставляются только точно, а сами имена перечисляются в отчёте.

Все совпадения, найденные **не** по точному имени, выписываются в отчёт отдельным
списком — стоит его проглядеть. Если нужно строгое поведение, есть `-Exact`.

## Отчёт

Рядом создаётся `_sort_music_report.txt`:

- сколько песен в каждой станции, сколько скопировано;
- **каких `.ogg` не хватает** (песня в станции есть, файла нет — обычно это песни
  из базовой игры или из другого мода), с подсказкой из похожих имён файлов;
- что сопоставилось не по точному имени (и как именно — `asset` или `norm`);
- какие `.ogg` не попали **ни в одну** станцию (мусор или забытые треки).

## Параметры

| Параметр | Что делает |
|---|---|
| `-DryRun` | только показать план, ничего не создавать и не копировать |
| `-Force` | перезаписать уже скопированные файлы |
| `-Exact` | только точные совпадения имён (без `.asset` и упрощённых имён) |
| `-Path "D:\...\music"` | работать не в папке скрипта, а в указанной |
| `-Extensions .ogg,.wav` | какие расширения считать музыкой (по умолчанию `.ogg .wav .mp3 .flac`) |

## Вариант на Python

`sort_music.py` — то же самое, если удобнее Python (или нужен не-Windows):

```bash
python sort_music.py --dry-run
python sort_music.py
python sort_music.py --path "D:/Steam/steamapps/workshop/content/394360/2213783261/music"
```
