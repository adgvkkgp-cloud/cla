# Таксономия лица

Справочник лица: анатомия и морфология, мимика и микровыражения, эстетика
и каноны, фенотипические черты, типажи и арт-теги в нотации Danbooru/Gelbooru.

**41 часть · 162 раздела · 2986 позиций**

## Как посмотреть

`TAXONOMY_FACE.html` — самодостаточный одностраничник, всё внутри одного файла.
На компьютере открывается двойным щелчком: сервер не нужен.

На телефоне — через `Запустить.bat` / `Запустить.command` в корне репозитория:
откроется страница с QR-кодом. Подробности — в корневом `README.md`.

Есть поиск по названию, описанию и тегу, лента частей, раскрытие разделов
и переключатель тегов. Клик по тегу ищет по нему.

## Сборка

```bash
node tools/check.cjs    # проверка целостности данных
node tools/build.cjs    # → TAXONOMY_FACE.html
```

Ни npm, ни node_modules, ни сборщика: обоим скриптам хватает `fs` и `path`
из самого node. Раньше, чтобы поменять в таксономии одну строку, требовался
`npm install` на 96 МБ с React, Vite и Tailwind.

Палитра в `src/palette.json` снята замером вычисленных стилей прежней сборки
на React — не подобрана на глаз, поэтому вид сохранился до значения цвета.

## Проверка целостности

`tools/check.cjs` роняет сборку, если корпус разошёлся сам с собой:
повторяющиеся названия позиций, повторяющиеся id разделов и частей, пустые
поля, дыры в нумерации внутри раздела, цвет раздела вне `src/palette.json`.

Главная из проверок — повтор названия. Именно так корпус и портился: части
дописывались поверх уже существующих, а не в них, и одна и та же черта попадала
в него по второму и третьему разу, каждый раз с чуть другим описанием. Вручную
это не ловится: к тому моменту, как повторов стало 152, разглядеть их в файле
на 4700 строк было уже нельзя.

Черта, которую нужно назвать дважды в разных рамках, называется по-разному:
«Высокие скулы» (анатомия), «Высокие скулы как канон красоты», «Высокие скулы
(южноазиатский тип)».

## Регистр описаний

Описание называет признак, по которому черту опознают глазом, и меру, если она
есть: «Лицевой индекс > 90», «угол прикрепления > 30°», «Рассеяние Тиндаля,
малый меланин», «видно больше 3 мм десны над верхним рядом». Не «Малая длина»,
а «Малая длина спинки, переносица к кончику идёт круто».

Три раздела живут по своим правилам, и короткая строка там — не пробел:

- **booru-разделы и арт-теги** — английский тег с русской глоссой
  (`smile` → «Улыбка»). Глосса переводит, а не пересказывает;
- **`facs-aus`** — описание называет мышцу (`Zygomaticus minor`), что для
  системы кодирования лицевых движений и есть ответ;
- **разделы комбинаций** (`combo-eye-brow` и подобные) — название задаёт
  сочетание черт, описание даёт его прочтение. В этом их смысл.

## Устройство

| Файл | Что это |
| --- | --- |
| `TAXONOMY_FACE.html` | Собранный одностраничник — всё в одном файле |
| `src/data.js` | Корпус: части → разделы → позиции. Обычный JS без сборки |
| `src/viewer.html` | Вьюер: разметка, стили и логика, без зависимостей |

## Две оси впечатления

Типажей в корпусе много — 23 раздела, — но все они именованные культурные
образы: Брутальный мужлан, Femme fatale, Tsundere. Это профильные понятия.
Общих слов, которыми лицо описывают целиком, не хватало, и не хватало
по-разному:

- **считываемый характер** (`character-impression`) в корпусе был: доброе,
  хитрое, волевое, непроницаемое лицо;
- **общее впечатление** — нет. «Миловидное», «невзрачное», «заурядное»,
  «грубое», «отталкивающее» не встречались вовсе; «впалое» было только
  по частям (щёки, виски), но не как лицо.

Вторая ось теперь есть, шестью разделами части XV: общее впечатление,
неотения в двух прочтениях, привлекательность мужская, женская
и андрогинная, непривлекательные конфигурации.

Неотения до этого была заведена одной стороной — как миловидность. Между
тем те же детские пропорции читаются противоположно в зависимости от того,
что рядом: крупные глаза при малом носе дают миловидность, те же глаза при
большом носе, скошенном подбородке и низкой средней зоне — нет. Оба
прочтения разведены.

Регистр здесь тот же, что во всём корпусе: не оценка, а конфигурация — какое
сочетание признаков так читается. «Впалое лицо» — не «худое и некрасивое»,
а «низкий жир при узкой кости: тени под скулами, запавшие виски и глазницы».
Поэтому позиция и пригодна для рисования.

### Формат

```js
entry   = { id, name, desc, tags }          // id — 1..n внутри раздела
section = { id, title, subtitle, color, entries }
part    = { id, title, emoji, sections }
```

`src/data.js` читается и браузером как `<script>`, и node — при проверке
целостности. Никакого промежуточного формата между ними нет.

`color` — одно из шестнадцати имён в `src/palette.json`. Раздел с цветом вне
этого списка проверка не пропустит.

## Что было починено

Приложение пришло отдельно и чинилось в четыре захода.

**Интерфейс.** 42 вкладки частей переносились по строкам: прилипшая шапка
вырастала до 1464 px при экране 844 px — 173 % экрана, — и нижние два десятка
вкладок нельзя было нажать ни при какой прокрутке. Лента теперь прокручивается
вбок одной строкой, шапка занимает 220 px. Подписи вкладок резались по 20 знаков
посреди слова («АНАТОМИЯ И МОРФОЛОГИ») — обрезка снята. «↓ все» разворачивало
все позиции разом (страница 285 000 px, раскрытие дольше секунды) — тело раздела
монтируется по попадании в поле зрения, строк в DOM после «↓ все» стало 15–27
вместо 3004.

**Повторы.** 143 названия встречались не по одному разу — 152 лишние копии,
5 % корпуса. У 115 из них описания расходились, причём поздняя копия обычно
была хуже ранней: «Лицевой индекс > 90» превращался в «Лицевой индекс высокий»,
число терялось. 136 копий слито в профильные разделы с лучшим из описаний
и объединением тегов, 16 получили уточнённые названия, потому что называли одну
черту в разных рамках.

**Описания.** 139 описаний пересказывали заголовок: «Кудрявые волосы» →
«Локоны», «Короткий нос» → «Малая длина», «Высокий хвост» → «Хвост на макушке».
141 описание переписано; осталось одно — «Цианоз», и это термин, а не пробел.
Медиана длины при этом почти не сдвинулась (26 → 27 знаков): переписанное —
5 % корпуса, а остальные описания хоть и коротки, но содержательны.

**Оснастка.** Приложение было на React, Vite и Tailwind: чтобы поменять
в таксономии одну строку, требовался `npm install` на 96 МБ, а собранный файл
весил 698 КБ. Вьюер переписан на обычный JavaScript, данные — из TypeScript
в обычный `.js`, сборка — в скрипт на `fs` и `path`. Ни npm, ни node_modules,
ни сборщика; файл стал 541 КБ. Чтобы вид не «поплыл», палитра снята с прежней
сборки замером вычисленных стилей и записана в `src/palette.json` — цвета
совпадают до значения.
